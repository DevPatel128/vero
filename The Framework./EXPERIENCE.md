# Product Experience

## Experience promise

What should the product feel like?

## Mental model

Explain the product in the simplest useful model a new user can understand.

## Experience hierarchy

1. What do I need to know?
2. What should I do?
3. Why does it matter?
4. Details.
5. Advanced controls.

## Core journey

Discovery → First value → Habit → Deeper value → Long-term outcome

## Information architecture

Define where information belongs and why.

## Progressive disclosure

What appears immediately?
What appears only when useful?
What is always available through navigation?

## Interaction principles

- Clear primary action.
- Minimal competing actions.
- Preserve context.
- Make important state visible.
- Explain consequential recommendations.
- Keep recovery easy.

## AI experience

Define:
- What AI can do.
- What AI cannot do.
- What requires research.
- How uncertainty is shown.
- How users correct AI.
- How user data grounds answers.

## Notifications

Only send notifications that create meaningful value.

## Accessibility

Define keyboard, screen-reader, contrast, motion, touch, language and cognitive-load requirements.

## Trust

State how the UI communicates permissions, data use, uncertainty, errors and irreversible actions.

## Change decision

For meaningful experience changes:

### Why should we make this change?

### What impact will it have?

### What results should it yield?

### How will we do it?

### How much will it cost?

### Is the cost justified?

Prefer the simplest experience and lowest-cost implementation that delivers the required user outcome.

## Quality gate

A feature is not experience-complete until it is understandable without documentation.
