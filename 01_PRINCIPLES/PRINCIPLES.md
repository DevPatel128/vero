# Principles

> Status: Review · Owner: Dev Patel · Version: 2 · Last updated: 2026-09-28
> Source: Wolf v3 framework, `01_PRINCIPLES/PRINCIPLES.md` (imported unchanged apart from this header; supersedes the v2 list this file held before)

This is the product constitution.

1. User value first.
2. Simplicity over unnecessary complexity.
3. Complexity belongs in the system, not the user's head.
4. Trust before growth.
5. User control.
6. No dark patterns.
7. Privacy by design.
8. Security by default.
9. Least privilege.
10. Evidence before confidence.
11. Research before consequential recommendations.
12. Never fabricate.
13. One source of truth.
14. Progressive disclosure.
15. Accessibility is part of quality.
16. Build the smallest honest version first.
17. Optimize outcomes, not activity.
18. Remove unnecessary complexity.
19. Minimize sensitive data.
20. Lowest justified total cost.
21. Computational efficiency is a requirement.
22. Use the minimum necessary code and infrastructure while preserving correctness, security, readability, maintainability and testability.
23. Human authority remains over consequential decisions.
24. Every consequential AI action must be attributable and auditable.

### Final test

Does this make the user's life clearer, safer, easier, or more capable?

If not, reconsider it.

### Relation to the v2 list

The v2 principles this file held (imported from the framework this repo adopted on 2026-09-21) are not contradicted by the above — they are largely restated in different words (e.g. v2's "Sincerity over sophistication" and "Notifications must earn attention" are specific applications of #1 and #6 here). Where v2 was more specific than Wolf's v3 list, the more specific guidance still applies as an application of these 24, not as a competing rule. Nothing here reverses a v2 principle.
