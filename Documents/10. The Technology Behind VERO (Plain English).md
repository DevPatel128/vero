# The Technology Behind VERO (Plain English)

This document explains the technology VERO uses — without the jargon. If you are a non-technical reader, you should be able to understand exactly how VERO works under the hood after reading this.

---

## The Big Picture

VERO is a web application. That means users access it through their internet browser — on their phone, laptop, or desktop. There is no app to download for Phase 1. (A native mobile app comes later.)

Behind the website is a set of computers (servers) that store data, process requests, and handle the work of running the platform. VERO does not own these computers — it rents them from trusted cloud providers.

---

## What VERO Uses, and Why

### The Framework — Next.js 15

A framework is a starter kit that handles the boring parts of building a website (routing, security, page loading) so the team can focus on the actual product.

**Why Next.js:** It is the industry standard for high-quality web applications. It is fast, secure, well-supported, and used by companies like Stripe, Notion, and Vercel itself. It also handles both the user-facing pages and the behind-the-scenes data work in one place.

### The Database — Supabase (PostgreSQL)

A database is where VERO stores everything: user profiles, job listings, work records, signatures, payments, and all the data that makes the platform work.

**Why Supabase:** Supabase is built on PostgreSQL, the most widely-respected database in the industry. It also handles user accounts, login, file storage, and real-time updates in one place — which means VERO can move faster without compromising on quality.

**What is stored:** profiles, jobs, applications, signed work records, escrow status, messages, disputes, audit logs, and so on. All of it is protected — only the right people can see the right data.

### User Login and Identity — Supabase Auth + Argon2id + JOSE

When you sign up for VERO, your password is never stored in plain text. It is "hashed" — turned into a scrambled string that cannot be reversed back into your original password.

**Why this matters:** If anyone ever managed to access VERO's database (extremely unlikely, but planned for), they would not be able to see anyone's actual password. Even VERO does not know your password.

**Argon2id** is the algorithm used to do this hashing. It is the current best-practice standard recommended by security experts globally.

**JOSE** is a library for handling secure tokens (the little pieces of data that prove you are logged in). VERO uses the strongest version of these tokens (RS256), which is significantly harder to forge than weaker alternatives.

### File Storage — Supabase Storage

When workers upload portfolio images, ID documents, or job deliverables, those files need to be stored somewhere safe.

**Why Supabase Storage:** Files are encrypted, access-controlled, and globally distributed for fast loading. Private files (like ID documents) are protected so only authorised people can see them.

### Payments and Escrow — Razorpay

When a business pays for a job on VERO, the money does not go directly to the worker. It goes into an escrow account — a holding place — until both sides agree the job is complete.

**Why Razorpay:** It is India's leading payment platform, fully licensed under Indian banking regulations (it holds a Payment Aggregator license from the Reserve Bank of India). It supports UPI, bank transfers, cards, and net banking — every way Indians actually pay for things.

### Real-Time Updates — Supabase Realtime

When a worker sends a message in a job thread, the business needs to see it instantly. When a job status changes from "in progress" to "completed", both sides need to know immediately.

**Why Supabase Realtime:** It provides the live update layer without requiring complicated extra infrastructure. Messages, status changes, and notifications appear instantly.

### Visual Design and Interface — TailwindCSS + shadcn/ui

These are the tools that make VERO look the way it does — clean, calm, premium, and consistent across every page.

**Why this combination:** TailwindCSS is the most efficient way to build a custom design system. shadcn/ui is a high-quality library of pre-built components (buttons, forms, cards) that look great out of the box and can be customised. Together they let VERO ship a polished product fast without sacrificing visual quality.

### Animations — Framer Motion + Lenis

Subtle motion — page transitions, button reveals, scroll smoothness — makes a product feel premium and intentional rather than static and cheap.

**Why these libraries:** Framer Motion is the industry standard for React animations. Lenis is widely used by award-winning websites for smooth scroll behavior. Used together, they make VERO feel polished without being distracting.

### Security Extras — Zod, CSRF Tokens, Rate Limiting

Three small but important things:

- **Zod** checks every piece of data coming into VERO's servers to make sure it is the right shape and type. This prevents a huge class of bugs and security issues.
- **CSRF tokens** prevent a specific type of attack where someone tricks a logged-in user into accidentally performing an action they did not mean to.
- **Rate limiting** stops anyone from making too many requests in a short time (for example, trying to log in with 1,000 different passwords in a minute).

### Error Tracking and Analytics — Sentry + PostHog

VERO needs to know when something is broken and how people are actually using the product.

- **Sentry** automatically catches errors and crashes so the team can fix them fast
- **PostHog** tracks anonymised user behavior (which buttons get clicked, which flows succeed) so the team can improve the product based on real usage

Neither of these tools captures personal data without user consent.

### Where VERO Lives — Vercel

The website itself is hosted on Vercel — a high-performance hosting platform built specifically for Next.js applications.

**Why Vercel:** Fastest possible page loads, global content delivery, automatic scaling when traffic spikes, and built-in security. It is used by major companies including OpenAI, Stripe, and the BBC.

## What VERO Does to Keep Your Data Safe

In plain language:

- **Strong passwords** — encrypted with Argon2id (the modern standard)
- **Secure logins** — tokens use the strongest signing method available
- **Encrypted storage** — files and sensitive data are protected
- **Row-level security** — even inside VERO's database, your data can only be seen by you and the people you have authorised
- **Soft deletes** — if you delete your account, your data is marked as deleted but kept in audit logs (required by Indian law). Real deletion happens after a retention window.
- **Audit logs** — every important action (login, payment, signature, dispute) is logged so it can be reviewed later if needed
- **No personal data in URLs** — your email, ID number, or phone number will never appear in a website address
- **DPDP Act compliant** — VERO meets the requirements of India's Digital Personal Data Protection Act 2023

## What Makes VERO Different Technically

Two things, beyond the standard stack:

### 1. The trust system (ALVED)

VERO's trust system is more than a star rating. It looks at multiple independent signals — completion rate, repeat clients, dispute history, endorsement quality — and combines them in a way that is hard to manipulate but easy for users to understand. This is built specifically for VERO and is one of the things that makes the platform meaningfully different.

### 2. Dual-signature work records

When a job is completed, both the worker and the client confirm it. This creates a permanent record that neither side can quietly edit later. The records are stored in VERO's database now, and over time will become anchored to blockchain infrastructure for full portability — but the core mechanism (two people, two signatures, one permanent record) works the same way regardless.

## What VERO Does Not Use (Yet)

These are technologies VERO is aware of but does not use in Phase 1:

- **Native mobile apps** — Phase 2. Web works well on mobile for now.
- **AI-powered job matching** — Phase 2+. Requires enough data to train a useful model.
- **Blockchain-anchored credentials** — Phase 5. Strategic, not Phase 1.
- **Complex microservices architecture** — not needed. Simple architecture wins until scale demands change.

The philosophy: do not add complexity until the value justifies it. Every tool VERO uses is there because it solves a real, current problem.
