# UI and UX Rules

## UX goal
The interface should feel like a premium, calm, app-native system that helps people understand the product quickly and act with confidence. The experience should reduce uncertainty, not increase it.

## Overall design principles
- mobile-first
- low cognitive load
- clear hierarchy
- clean spacing
- minimal clutter
- fast interaction feedback
- accessible by default
- simple navigation
- predictable patterns
- subtle motion only when useful

## Visual hierarchy
Use a strong visual hierarchy so the user always knows:
- what the page is about
- what matters most
- what action to take next

Primary content should be easy to scan. Secondary content should support the main message, not compete with it.

## Layout rules
- Use generous whitespace.
- Keep line lengths readable.
- Avoid dense blocks of text.
- Break content into cards, sections, and steps.
- Ensure consistent alignment.
- Keep section heights balanced.
- Preserve rhythm across pages.

## Motion rules
Motion should:
- reinforce structure
- guide attention
- create calm delight
- never block usability

Use motion for:
- page transitions
- card reveals
- small hover states
- progress steps
- trust growth visualization

Avoid:
- jitter
- overuse of parallax
- flashy animations
- motion that slows down reading
- motion that distracts from the meaning

## Interaction rules
Every interactive element must:
- look clickable
- respond instantly
- show loading or disabled states
- support mobile touch
- have accessible focus states
- show error states clearly
- behave consistently

No dead buttons. No fake controls. No placeholder UI that feels unfinished.

## Mobile rules
The mobile experience is primary. Design for:
- one-handed use
- small screens
- slow networks
- low-end Android devices
- touch first interactions

Important mobile behaviors:
- sticky bottom nav when appropriate
- large tap targets
- compact but readable sections
- collapsible long content
- minimal input friction
- optimized image loading

## Accessibility rules
- semantic HTML
- proper heading order
- contrast compliance
- keyboard navigation
- screen reader-friendly labels
- visible focus states
- accessible form feedback
- color-independent meaning
- scalable text

## UX trust rules
The interface should reduce fear and increase confidence. Avoid ambiguous labels, unclear affordances, and overloaded pages. If a user can misunderstand an action, the UI is not ready.

## Information design
Every page should answer one of these questions:
- What is this?
- Why should I trust it?
- How does it work?
- How do I start?
- What happens next?

## Performance as UX
Speed is part of user experience. Slow pages, jumpy animations, and delayed responses reduce trust. Treat performance issues as UX issues.

## Copy and UI alignment
The copy, layout, and interaction patterns must support each other. Premium copy with a cluttered layout feels fake. Clean layout with unclear copy feels weak. Both must be strong.

## Final rule
If a design choice does not improve clarity, trust, or usability, remove it.
