# Blockchain System

## Objective
Use blockchain only where it produces meaningful trust, verification, payment, and portability benefits. Blockchain should not become the brand identity. It is an infrastructure layer, not a gimmick.

## Core principle
VERO is a proof-of-work identity platform first. Blockchain exists to strengthen trust, transparency, payments, and portable reputation. The user experience must remain mainstream-friendly and simple.

## What blockchain should help with
- secure payments
- transparent escrow
- portable identity
- verifiable reputation records
- immutable certificates
- cross-border payouts
- trust portability
- fraud resistance

## What blockchain should not do
- no speculative token launch
- no crypto-first brand
- no NFT marketplace hype
- no complex wallet friction for beginners
- no unnecessary on-chain data exposure

## Recommended blockchain use cases
1. Portable proof-of-work identity
2. On-chain reputation snapshots
3. Verifiable work certificates
4. Smart contract escrow
5. Stablecoin payments
6. Reputation passport
7. Signed references and endorsements
8. Fraud-resistant records
9. Non-transferable skill credentials
10. Transparent dispute logs
11. Micro-incentive systems
12. Portable trust history

## Payments
Support stablecoin rails where they are useful:
- USDC
- USDT
- optional future assets if they fit the product

Use blockchain payments for:
- gig payouts
- apprenticeship payouts
- creator payouts
- cross-border transfers
- bonuses
- escrow releases

Users should still be able to use normal fiat payment experiences. Crypto should be optional or abstracted away.

## Escrow
Use smart contract escrow only where it clearly improves trust and reduces disputes. Support:
- milestone-based release
- hold-and-release logic
- dispute holds
- transparent payout records
- client and worker protection

## Reputation portability
The platform should eventually let users carry verified work identity, endorsements, and credentials across systems. This is a long-term vision. The data should be structured so it can later map to external ecosystems.

## Soulbound credentials
Use non-transferable credentials for:
- skill verification
- apprenticeship completion
- ambassador recognition
- trust milestones
- verified contributions

Do not make these collectible or speculative.

## Identity and wallet UX
If wallets are used, the onboarding must still feel simple. Support embedded wallets and familiar login flows so mainstream users do not need deep crypto knowledge.

## Security
Blockchain logic must be protected by:
- signature verification
- transaction validation
- secure contract design
- rate limiting
- anti-fraud rules
- wallet recovery strategy
- moderation oversight

## Privacy
Do not expose sensitive identity data on-chain unnecessarily. Prefer hashes, proofs, or minimal attestations when possible.

## Chain preference
Prefer low-fee, mainstream-friendly ecosystems. The architecture should stay flexible so the team can choose the right chain or provider later.

## Website language
The website should explain blockchain as trust infrastructure, not as a speculative crypto story. The language should be calm, useful, and clear.

## Product outcome
The blockchain layer should make VERO feel more credible, more scalable, and more globally useful without making the product harder to use.
