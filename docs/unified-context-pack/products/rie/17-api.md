# 17 — API

## Goal
Document the surfaces that ingest proof and serve product data.

## Must cover
- Public routes
- Authenticated routes
- Integrations and webhooks
- Idempotency rules
- Error handling
- Versioning

## API rule
Proof-related APIs should be deterministic and easy to audit.

## Anti-patterns
- Unclear webhook behavior
- Undocumented state transitions
- Silent breaking changes
