# Onboarding System

## Objective
Build onboarding that helps users immediately understand VERO and quickly reach a meaningful first action. Onboarding should lower confusion, reduce friction, and build trust.

## Onboarding philosophy
The user should feel:
- this platform is for me
- I understand what it does
- I know why it is different
- I can start without being overwhelmed
- I can trust it

## Primary onboarding goals
1. explain the product
2. select user type
3. select career path
4. collect only necessary details
5. create early trust
6. guide users to their first success

## User types
Support:
- apprentice
- worker
- beginner
- student
- career switcher
- client
- household
- business
- ambassador
- mentor

## Apprentice onboarding
For people seeking growth, the flow can include:
- welcome
- career path choice
- skill level
- goals
- identity verification
- portfolio creation
- micro-learning
- skill assessment
- trust profile activation

## Client onboarding
For clients, the flow should capture:
- business type
- location
- booking needs
- budget
- frequency
- trust expectations
- support requirements

## Friction reduction rules
- ask only necessary questions
- show progress indicators
- make steps visually obvious
- avoid long forms
- allow skip later where safe
- explain why data is needed
- keep the first session short

## Trust-building during onboarding
Build confidence by showing:
- verification steps
- how trust works
- what profile data does
- how the platform protects users
- what happens after signup

## UI patterns
Use:
- step cards
- progress bars
- selection chips
- simple modals
- clean form fields
- success states
- trust reassurance blocks

## Micro-learning
For some users, onboarding can include tiny skill or platform lessons. These should not feel like school. They should feel like a fast orientation to the platform and the work path.

## Emotional goal
The onboarding should reduce fear. Beginners should feel capable. Clients should feel safe. Ambassadors should feel respected. The platform should never feel like a confusing gate.

## Completion rule
By the end of onboarding, the user should have:
- a clear identity type
- a clear path
- a clear next step
- a sense of trust
- a desire to continue

## Best practice
The first experience should feel like momentum, not paperwork.
