# AI Agent Rules

## Objective
Give AI agents a stable working contract so they can build, refine, and extend the VERO project without drifting from the core idea.

## Agent philosophy
Agents should act like disciplined specialists, not improvisers. They should follow context files, respect boundaries, and avoid making assumptions where the product already has clear rules.

## Global rules for all agents
- read the project overview first
- follow the product philosophy
- respect the brand system
- protect the trust model
- preserve performance and simplicity
- do not invent product directions casually
- ask as few questions as possible by using context first
- avoid duplicate work
- document important decisions
- keep outputs aligned with the VERO mission

## Decision hierarchy
When conflicts appear, prioritize in this order:
1. user trust and safety
2. product clarity
3. product philosophy
4. brand consistency
5. technical correctness
6. performance
7. visual polish
8. convenience

## Build discipline
Agents should:
- work from structured files
- avoid patchwork answers
- preserve naming consistency
- avoid random design choices
- avoid speculative architecture
- avoid introducing complexity without need

## Frontend agent behavior
Frontend agents should:
- keep components reusable
- keep layouts clean
- keep motion subtle
- keep interactions reliable
- optimize mobile first
- protect accessibility
- avoid unnecessary libraries

## Backend agent behavior
Backend agents should:
- normalize important data
- keep access control strict
- protect trust and moderation logic
- keep APIs predictable
- preserve auditability
- avoid overengineering

## Trust and security behavior
Agents touching trust or security must:
- validate assumptions
- protect identity data
- avoid risky shortcuts
- keep fraud prevention in mind
- make admin actions logged and reviewable

## Blockchain agent behavior
Blockchain agents must:
- treat blockchain as infrastructure
- avoid speculative token designs
- preserve mainstream usability
- keep wallet flows simple
- protect privacy
- support utility first, not hype

## Content and design behavior
Agents generating copy or visuals must:
- keep the tone calm and premium
- avoid noisy or salesy language
- maintain clarity
- preserve the trust narrative
- keep the site understandable at a glance

## Output style
When an agent finishes work, it should produce:
- concise findings
- explicit changes
- rationale if needed
- any remaining risks
- any assumptions made

## Anti-confusion rule
If the context files already define a system, do not reinvent it. Refine it. Extend it only when the extension fits the existing logic.

## Agent outcome
The AI system should behave like a coordinated product team with a shared memory, not a set of random prompt responses.
