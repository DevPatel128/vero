# Trust System

## Objective
The trust system is the core moat of VERO. It must make the platform reliable for users, clients, and the business itself. The system should measure credibility without becoming opaque or easy to game.

## Trust philosophy
Trust should be earned through real behavior, not claimed through profile copy. Every trust signal should reflect a real-world action. The user should be able to understand how credibility is built and how to improve it.

## Trust signals
Use multiple signals rather than a single score. Examples:
- verified completions
- attendance reliability
- punctuality
- cancellation rate
- dispute rate
- repeat-client ratio
- proof quality
- client ratings
- endorsement quality
- consistency over time
- role-specific performance
- background verification where needed

## Trust score design
The trust score should:
- be weighted
- be explainable
- update over time
- be hard to game
- vary by category if needed
- be visible enough to be useful
- not be so simple that it can be manipulated

## Category-aware trust
Different career fields may need different trust emphasis. For example:
- elder support should emphasize safety and background checks
- pet care should emphasize reliability and repeat trust
- beauty and wellness should emphasize quality and portfolio proof
- hospitality should emphasize punctuality and professionalism
- creative work should emphasize portfolio and client satisfaction

## Verification rules
Verification can use:
- government ID
- phone and email verification
- photos or videos
- location checks where appropriate
- client confirmation
- mentor confirmation
- platform moderation
- background verification for sensitive roles

## Dispute system
A dispute flow should include:
1. user reports issue
2. evidence is collected
3. automated checks run
4. moderator review if needed
5. decision is recorded
6. trust score updates if appropriate

The system must protect both sides. It should not assume every complaint is true. It should not ignore legitimate harm.

## Escrow and trust
Escrow is part of trust. If money is involved, the platform should reduce payment fear by holding funds safely and releasing them according to agreed terms or milestones.

## Client credibility
Not only workers should have reputation. Clients should also have trust indicators such as:
- payment reliability
- cancellation behavior
- clarity of instructions
- review history
- dispute frequency
- repeat booking consistency

This creates a healthier marketplace.

## Anti-gaming rules
The trust system must resist:
- fake reviews
- sybil accounts
- trust farming
- repeated low-value bookings
- manipulated endorsements
- collusive ratings
- fake uploads

Use multiple independent indicators to reduce manipulation.

## Public versus private trust
Some trust data should be public, such as badges, categories, and general reputation. Sensitive data should stay private. The trust system must respect privacy while still building confidence.

## User understanding
The user should always know:
- what trust means
- how it changes
- how to improve it
- what actions lower it
- what is required for higher-trust categories

## Long-term value
The trust system should eventually support portable proof-of-work identity, credibility graphs, and verified career history that can be reused beyond VERO.
