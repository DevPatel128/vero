# Documentation System

## Goal
FIND → UNDERSTAND → DECIDE → ACT.

Every concept has one canonical home.

## Structure
```text
00_START_HERE/
01_PRINCIPLES/
02_PRODUCT/
03_RESEARCH/
04_DESIGN/
05_ENGINEERING/
06_OPERATIONS/
07_BUSINESS/
08_DECISIONS/
09_AUDIT/
10_ARCHIVE/
```

## Rules
- Audit the documentation before restructuring it.
- Do not duplicate canonical information.
- Create a new document only for a genuinely distinct, repeatedly referenced concept.
- Each major folder has a README.
- Major documents carry status, owner, version and last-updated metadata.
- Approved documents are not silently overwritten.
- Superseded material is archived.
- When code, product, research, design, business, architecture, policy or security changes, automatically determine documentation impact.
- Report CHANGE / WHY / FILES AFFECTED / EVIDENCE / RISKS / APPROVAL.
- Every AI task reports canonical documents consulted.

## Documentation quality test
A new human or AI must have exactly one obvious starting point for:
product, thesis, research, experience, architecture, security, implementation, deployment, incidents, business model, investor narrative, decisions and audit history.
